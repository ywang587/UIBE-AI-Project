## 下一段工作及完成标准

1. 接续可访问的执行环境并检查可移植性
   - 将本项目仓库克隆到选定的执行环境并作为主工作目录；不预设后续实验全部在用户本机。
   - 在用户允许访问的材料目录中找到已有 MediaCrawler 和转录程序；若材料仅在用户本机，需先在可访问该目录的会话读取。
   - 读取已有 AGENTS.md 等适用说明，检查 Git 版本、改动与运行入口；不执行未知启动文件后才检查。
   - 记录可复现的依赖和启动方法，用相对路径或配置替代旧机器绝对路径。
   - 完成标准：说明哪些成果可复用、缺少什么；核心路径可配置，在不同目录布局复验，并记录实际测试环境。不要要求用户打包虚拟环境、缓存或登录状态。

2. 验证单链接内容获取
   - 使用同一条样本的短链接和长链接，确认映射到相同视频 ID。
   - 检查完整视频或音频能否取得、可播放，并保存作者、发布时间、原链接。
   - 复用原本有效的采集逻辑；尊重平台访问限制，不绕过验证码或反自动化控制。
   - 完成标准：文件真实可用，失败有明确原因，没有重复记录；不将页面访问成功写成下载成功。

3. 验证转录并形成第一份分析样例
   - 复用中文转录流程，保留时间位置；核对开头、中间、结尾及关键数字、术语。
   - 提取博主主张与原文证据，外部背景及事实核查单独呈现，不补造因果机制。
   - 完成标准：能够回到原文核对，缺失与不确定性可见。
   - 开发 AI 自检不等于独立标注正确率；如未开展独立评估应明确记录。

4. 小范围验证博主作品获取
   - 优先核查现有 creator 模式是否能取得最近少量作品的 ID、标题和时间。
   - 不默认遍历、下载全部历史作品；先评估是否需要限制范围。
   - 后续实现已处理 ID 去重、失败重试、按上次成功检查补查。
   - 完成标准：重复检查能识别新增与已处理作品，并如实标记遗漏风险。

5. 再接跨视频对照与界面
   - 对同一事件的可比较材料呈现相近、分歧、互补或无法比较。
   - 单条先显示，后续新增材料再更新对照。
   - 程序内查看、历史、原视频入口与状态提示优先；不提前扩展多用户、商业系统或训练模型。
