# 观潮本地应用验证

日期：2026-10-13。用户选择先用本地模型跑通，不接付费 API。本文记录实际运行结果，不是金融分析准确率报告。

## 环境与实现

在 macOS arm64、8GB 内存设备运行，分析使用 `mlx-community/Qwen3-4B-Instruct-2507-4bit`、MLX LM 0.32.0、Outlines 1.3.3。转录仍使用 Faster-Whisper medium、CPU、int8。各步骤串行执行，分析子进程退出后释放模型内存。

新增本机浏览器应用，覆盖视频/链接导入、持久队列、历史、原视频播放、时间定位、主张证据、关注博主、启动补查、事件简报和视频对照。模型、媒体、转录、数据库及登录状态留在 `local_data/` 或既有课程目录，不提交 GitHub。

## 关注与补查

使用既有 MediaCrawler 登录会话，没有触发新登录。Kevin 主页的首次有界扫描取得 14 条近期作品，2 页，到达早于回查范围的整页。随后从保存的成功检查点重新启动检查，1 页成功返回，未发现新的作品。

保存视频 ID 去重；失败或分页不完整时保留旧检查点。当前设备启用了每 60 分钟检查，自动处理全部新发现未开启。主页列表的排序、置顶、隐藏、删除和平台行为仍可能造成遗漏，不能宣称完整历史覆盖。

## 发现的错误与修复

1. 自由生成把几十个片段编号挂在同一条主张下。短视频成功不代表长视频可用；两条长视频均曾因引用范围过宽失败。缩短输入、普通重试不足以修复。随后加入结构约束，先选择最多 4 个真实片段编号再写主张；所有片段仍分组送入模型，没有截掉结尾。
2. 生活视频最初被误判为财经相关。加入独立领域筛选，明确区分金融投资讨论和个人生活、旅行；重跑后仅保留无关记录。
3. 合成案例中，模型将短期下跌与长期上涨错误标为分歧。调整为先判断同一问题、可比期限和条件，再输出关系；校验器拒绝维度不匹配的分歧。三个对照案例复测通过。
4. 旧对照仅保存主张编号，重新分析后可能错配。现在保存对照生成时的主张、原文和来源快照。
5. 补上重复启动锁，防止第二个服务重置第一个服务的活动队列；修复原文件丢失后重新导入无法修复播放路径的问题。
6. 每次视频处理保留独立运行目录；失败记录不会被后续重试覆盖。浏览器刷新保留视频播放位置与所选对照项。

## 测试与界面

- `python -m unittest discover -s tests -q`：23 项通过。覆盖去重、并发导入、重启恢复、重复进程、失败检查点、缺失原文件恢复、证据编号、对照快照及接口边界。
- 真实模型合成检查：4 项提取/筛选案例通过；初次 3 项对照中有 1 项失败，修复后 3 项复测通过。保留 [初次结果](2026-10-13-synthetic-initial.json) 和 [对照复测](2026-10-13-comparison-final.json)。这是已参与开发的案例，不是独立评估。
- Chromium 实测：原视频加载、时间定位、发现列表、无效输入提示、事件简报排除无关视频；390px 宽度没有横向溢出，没有页面脚本错误。
- 从详情界面选择印度与日本两个真实样本发起对照，任务完成并显示“无法比较”，双方引文保留。这个结果只验证拒绝不同事件的路径，不证明真实同事件跨博主对照准确。

## 尚未解决

结构与编号有效不等于语义准确。人工开发复查仍发现部分因果解释被归入事实性主张、概述包含未被当前少量引文完整覆盖的信息；自动结果必须回看原文。缩短输入与结构约束也可能影响重要观点覆盖，不能只按“任务完成”评价质量。

当前没有自动外部事实核查，没有真实同事件跨博主的独立评估，也没有长时间连续采集稳定性结论。事件简报仅整理已导入材料，不代表完整市场新闻。MLX 后端只在 Apple Silicon 上运行过；Windows/Linux 推理后端尚未实现。
